# 会議ノートの UI を作り直す（Mac）

- 状態: 2026-11-09 に了承し、実装した（spec の REQ-MTG-050〜054・DEC-MTG-130〜138 に移した）。実装のときに変えたことは末尾の「実装のときに変えたこと」
- 依頼: 2026-11-09「hanasu の会議ノートの UI もモダンに変更したい。どのような UI が良いかを考え、タスクを洗い出して要件を定義し、要件に沿ってモダンな UI を考えて。似たアプリの事例を GitHub などで調べ、UI/UX の観点でどんな体験を提供すべきかを踏まえてデザインして」
- デザインの見本: [meeting-notes-ui/](meeting-notes-ui/)（4 つの状態の `.dc.html`。Claude の Design のキャンバスで描いたもの）。見た目（余白・カード・帯の色・ツールバーのまとまり）は見本で決め、要件と設計判断は構成と振る舞いを決める。

## 目的

会議ノート（Mac の `MeetingWindowView`）は、機能を足すたびに上のボタンとタブが増え、今は次のようになっている。

- 上の 1 行に「話者名…」「議事録を作り直す」「書き出し」「Finder で表示」「削除」のボタンが並び、日時の行が折り返す（「10:00・21:00」と、長さが時刻のように見える）。
- エラーが、オレンジの長い文章として見出しの下に出る。
- 「議事録・文字起こし・メモ・ここ重要・AI チャット」の 5 つのタブを切り替えないと、議事録と元の発言を見比べられない。
- 議事録は Markdown をそのまま並べただけで、アクションアイテム（いちばん使う情報）が下の方に埋もれる。
- 左の一覧は日付で区切られず、下の欄にスピーカー・マイク・議事録の型の選択がいつも場所を取っている。

これを、**「要約とやることを最初に読み、根拠の発言と音声をその場で確かめ、すぐ行動に移せる」** 画面にする。

### 調べたこと（似たアプリと UI/UX の考え方）

| 事例 | 取り入れること |
| --- | --- |
| Granola | 本人のメモが主役で、AI が補う。各要点から元の文字起こしへ戻れる（虫めがねの印）。型を選び直して作り直せる |
| Notion AI Meeting Notes | 要約の各要点に引用（citation）を付け、押すと文字起こしのその位置へ移る。メモ・要約・文字起こしが 1 枚のページにある |
| Grain / Otter / Fathom | 文字起こしの発言を押すとその位置から再生。再生位置の発言が光る。タイムラインに誰が話したかと印を出す。アクションアイテムは要約の先頭 |
| Hyprnote（現 anarlog・OSS）/ Meetily（OSS） | ボットなし・ローカルの文字起こし。生成した議事録を文書のように読み、Markdown で書き出す |
| macOS 26（Liquid Glass）の決まり | 標準の `NavigationSplitView`・ツールバー・`inspector` を使い、ガラスを重ねない。操作はツールバーにまとめ、補助の情報はインスペクタに出す |
| MeetScript（HCI の研究） | 文字起こしの読みやすさが信頼を左右する。注釈は発言の上に残す |

ここから、次の 5 つを体験の原則にする。

1. **結果が先、材料はあと**: 開いたら最初に要約と「やること」が目に入る。文字起こしは右の補助に置く。
2. **AI の文は確かめられる**: 議事録の要点から根拠の発言へ 1 クリックで移れる。音声でも聞き直せる。
3. **同じ会議のまま移り変わる**: 記録を止めても選んでいる会議は変わらず、同じウインドウの中で、記録中の画面から議事録の文書へ替わる。
4. **操作は 1 か所**: 会議への操作はツールバーとその「…」のメニューにまとめ、本文には内容だけを置く。
5. **状態は控えめに、でも見落とさせない**: 作成中・古い議事録・失敗・音が入らない警告は、本文の上の帯で、次にすることのボタンと一緒に出す。

## 要件の案

計画の中では R1〜R5 と呼ぶ。spec に書くときは REQ-MTG の 050〜054 番にする（使っていないまとまり。開いている PR #78 は 120 番台を使う）。

### R1 記録した会議は、真ん中の文書と後ろ側のパネルで、議事録と元の発言を並べて読める（新規）

- 内容: 記録した会議を選ぶと、真ん中に「要約・アクションアイテム・議事録・ここ重要・メモ」を上から順に 1 枚の文書として出し、後ろ側（左から右に書く言語では右）のパネルに「文字起こし」と「AI チャット」を切り替えて出す。タブを切り替えなくても、議事録を読みながら文字起こしを見られる。
- 受け入れ条件:
  - 会議を選ぶと、真ん中の文書の上から、タイトル（変えられる）・日時と長さと参加者・状態の帯（あれば）・要約・アクションアイテム・議事録の残りの本文・「ここ重要」・メモの順に出る。
    - 要約は、議事録の最初の `## ` の節（型の既定では「概要」）。最初の節がなければ要約の欄は出さない。
    - アクションアイテムの欄は、取り出したアクションアイテム（`Meeting.resolvedActionItems`）が 1 つ以上あるときだけ出し、そのときは本文の「## アクションアイテム」（型によって「次のアクション」「次のステップ」）の節を本文に重ねて出さない。取り出したものが 0 件なら、その節を本文のまま出す。
    - 「ここ重要」の印がない会議では「ここ重要」の欄を出さない。メモの欄はいつも出し、空なら書き足せることを案内する。
  - 後ろ側のパネルの上に「文字起こし｜AI チャット」の切り替えがあり、どちらを選んでも真ん中の文書は見えたまま。パネルはツールバーのボタンと ⌥⌘I で隠せる・出せる。幅はドラッグで変えられる。
  - ウインドウの最小の大きさ（D1）で後ろ側のパネルを出したまま、真ん中の文書の幅が 400pt 以上ある。`--render-meeting-window` で最小の大きさ・パネルあり・発言を選ぶ状態を描き、中身の高さと幅がウインドウを超えない（NG が出ない）。
  - 検索で議事録の行を選ぶと、その行（要約・本文のどちらに出ていても）へスクロールして色を付ける。アクションアイテムの節の行なら、アクションアイテムの欄の同じ順番の行へ移る（順番が合わなければ欄の先頭）。
  - 今までのタブでできたこと（議事録・文字起こし・メモの編集・ここ重要の前後の会話・AI チャット・議事録に使う発言の選択・検索から飛ぶ・話者名・作り直し・書き出し・Finder で表示・削除）は、すべてこの画面でできる。
  - 「質問」（過去の会議への質問、REQ-MTG-016）を開いている間は、後ろ側のパネルを出さない。
- 出典: 2026-11-09 の依頼「会議ノートの UI をモダンに」、同日に構成を確かめた（文書＋右パネル）
- 対象: Mac（Windows は今のタブのまま。FUT-206）
- 実装の場所: `MeetingWindowView`、新しい `MeetingDocumentView`・`MeetingInspector`（`MeetingDetailView` を置き換える）
- 確かめ方: `--render-meeting-window`（足す）の PNG を UI のテスト項目で見る。`--render-meeting-search`（今ある）で、アクションアイテムの節の行に当たったときの飛び先を描く

### R2 会議の一覧は日付でまとめ、記録の操作は 1 つのボタンと 1 行の設定にする（新規）

- 内容: 左の一覧を「記録中・今日・昨日・今週・先週・それより前（月ごと）」に分けて出す。一覧の下は「会議の記録を開始」のボタン（記録中は「記録を停止」）と、その下の今の設定の 1 行にする。1 行を押すと、スピーカー・マイク・議事録の型を選べる小さなパネルが出る。
- 受け入れ条件:
  - 一覧の見出しが日付のまとまりになり、各行にタイトル・開始の時刻・長さ、作成中なら回る印、失敗なら「失敗」が出る。
  - 一覧の下に、記録していないときは「会議の記録を開始」、記録中は「記録を停止」、準備中・処理中は進み具合が出る。その下に「定例 · Mac 全体の音 · システムのマイク」のような今の設定の 1 行が出る。1 行を押すとパネルが出て、スピーカー・マイク・議事録の型と、型の管理（REQ-MTG-042 の管理のシート）を選べる。記録中・処理中は変えられない（今と同じ）。
  - 記録を始められなかったとき（権限・モデル・認証がないなど。`recorder.lastError`）は、今と同じくボタンの下に理由を出す。
  - 右クリック・⌫ での削除、検索、「質問」は今と同じに使える。
- 出典: 2026-11-09 の依頼「会議ノートの UI をモダンに」
- 対象: Mac
- 実装の場所: `MeetingWindowView.sidebarList`、`MeetingRow`、`RecordButton`、新しい `RecordSettingsPopover`
- 確かめ方: `--render-meeting-window --now "2026-11-09 12:00"`（基準の日時を固定して、今日・昨日・今週・先月の会議を置く）

### R3 議事録の要点から、根拠の発言へ移れる（新規）

- 内容: 議事録を作るとき、AI に要点ごとに根拠の発言の時刻を付けさせる（Mac と Windows で同じ指示）。Mac の会議ノートでは、議事録の本文とアクションアイテムの時刻を小さな印として出し、押すと文字起こしのその発言へ移って強調する。書き出しでは印を取り除く。
- 受け入れ条件:
  - 議事録のプロンプトに、要点の箇条書きの行末に根拠の発言の時刻を `[12:34]`（1 時間を超えたら `[1:02:34]`）の形で 1〜2 個付ける指示と、アクションアイテムの JSON に任意の `"at"` を付ける指示が、17 言語で入る（Mac と Windows で同じ文面）。
  - Mac の会議ノートで、議事録の本文とアクションアイテムの欄に時刻の印が出る。印を押すと、後ろ側のパネルが文字起こしに切り替わり（隠れていれば出し）、その時刻（1 秒の幅を見る）までに始まった最後の発言へスクロールして背景に色を付ける。音声を再生中なら、その位置へ移る（再生していなければ再生は始めない）。
  - 会議の長さを 1 秒より多く超える時刻の印は、薄く出して押せないようにする（作り話の時刻を見分けられる）。
  - 移った先の発言が議事録から除いた発言（REQ-MTG-045）でも移り、その発言は今と同じ薄い見た目で出る。
  - ローカルの AI・Apple の AI で、文字起こしを部分ごとの要点にまとめてから議事録を作ったとき（DEC-COM-065）は、議事録から時刻の印を取り除いてから保存する（まとめた入力には根拠の時刻がないため）。
  - 書き出し（Markdown のコピー・.md / .txt の保存・Slack 向け・リマインダー）には印を入れない。会議フォルダの `minutes.md` と `meeting.json` には残す。
  - Windows 版は、議事録の表示と書き出しで印を取り除く（押せる印にはしない。FUT-206）。
  - 引用のない今までの議事録は、今までどおりに読める。
  - 指示に従って AI が実際に印を付ける割合は、`--minutes-from-transcript` のサンプルで見る参考値とし、合否の条件にはしない。
- 出典: 2026-11-09 の依頼「会議ノートの UI をモダンに」、同日に「議事録→発言への引用」を足すこと、書き出しでは消すこと、Windows にも同じ指示を入れることを確かめた
- 対象: Mac / Windows（Windows は指示と、印を取り除くことだけ）
- 実装の場所: プロンプトの新しいキー `minutes.citations`（17 言語）、Mac の `MinutesPrompt`・Windows の `MinutesPrompt`（`MinutesTemplate.cs`）、新しい `MinutesCitation`（印の取り出し・取り除き）、`ActionItem.at`、`MeetingExport`・`ReminderExporter`、Windows の `MeetingExport`
- 確かめ方: `--test-minutes-citations`（足す。プロンプトに指示が入る・17 言語・印の取り出し・`[h:mm:ss]` と全角の［］・長さを超える印・書き出しとリマインダーで消える・要点にまとめたときに消える・`ActionItem.parse(fromMarkdown:)` が行末の印に乱されない）、`--minutes-from-transcript <文字起こし.txt>`（Gemini・`--ai local`・`HANASU_FM_PATH=… --ai apple` で実際に作って見る）、`cd windows && dotnet test Hanasu.Core.Tests`（議事録の指示に引用の指示が入る・表示と書き出しで印が消える・`at` を読み書きで落とさない）

### R4 残した音声を再生し、再生位置の発言を文字起こしで示す（新規）

- 内容: 音声ファイル（`me.m4a`・`others.m4a`）を残した会議では、文書の下に再生のバーを出し、2 つのチャンネルを重ねて再生する（片方ずつ消音できる）。再生中は、今の位置の発言を文字起こしで強調し、その発言が見えるようにスクロールする。文字起こしの発言の時刻を押すと、そこから再生する。
- 受け入れ条件:
  - 再生のバーに、再生・一時停止、15 秒戻る・進む、今の時刻と長さ、位置のスライダー、速さ（1×・1.25×・1.5×・2×）、「自分」「相手」の消音の切り替えがある。スライダーには話者ごとの色で話した区間と、「ここ重要」の印の位置が出る。
  - 再生すると、消音していないチャンネルの声が聞こえ、文字起こしで今の位置の発言の背景に色が付く。強調は、発言の開始の時刻から 0.5 秒以内に移る（チャンネルのずれを持たない古い会議は除く）。ユーザーが文字起こしを手でスクロールしたら自動のスクロールを止め、「再生位置へ」のボタンで戻る。
  - 文字起こしの発言の時刻を押すと、その発言の開始から再生する。
  - スペースキーで再生・一時停止する（文字の入力欄にフォーカスがあるときを除く）。
  - 次のときは再生のバーを出さない: 音声ファイルが両方ない会議（残さない設定・消した）、記録中の会議、処理中・議事録の作り直し中の会議。
  - 片方のチャンネルだけあるときは、ある方だけを再生し、ない方の消音の切り替えを押せなくして「相手の音声はありません」のように出す。
  - 読み込めない音声（途中で落ちた会議など）では、バーに「この音声は再生できません」と出し、再生のボタンを押せなくする。
  - 会議を記録している間と音声入力をしている間は、再生を止め、再生のボタンを押せなくして理由を出す（再生した音がマイクに入るため）。
  - 別の会議を選んだ・ウインドウを閉じた・スリープした・アプリを終了したら、再生を止める。
- 出典: 2026-11-09 の依頼「会議ノートの UI をモダンに」、同日に「音声の再生と同期」と消音を足すことを確かめた
- 対象: Mac
- 実装の場所: 新しい `MeetingPlayer`（`AVMutableComposition` に 2 つの音声を重ね、`AVPlayer` で再生）、`MeetingPlayerBar`、`MeetingInspector` の文字起こし
- 確かめ方: `--test-meeting-player`（足す。音声の組み立て・チャンネルのずれ・片方だけ・読めないファイル・時刻から発言を引く・0.5 秒以内に強調が移る・記録中と音声入力中は押せない）、実機で再生して聞く

### R5 記録中の画面と、記録を止めてから議事録ができるまで（新規）

- 内容: 記録中は、真ん中に文字起こし（リアルタイム）、後ろ側のパネルに「メモ｜AI チャット」を出す（今の並び）。記録を止めると、同じ会議を選んだまま、真ん中が議事録の文書に、後ろ側のパネルが「文字起こし｜AI チャット」に替わり、文書の上の帯に処理の進み具合が出る。
- 受け入れ条件:
  - 記録中、ツールバーに記録中の印・経過時間・自分と相手の音量・オフレコ・字幕・パネルの表示の切り替えがある。「★ ここ重要」は後ろ側のパネルの上に、「メモ」「AI チャット」のどちらを選んでいても出る（今の DEC-MTG-080 のまま）。停止は一覧の下のボタンと、メニュー・ショートカット（今と同じ）。ツールバーが狭くて項目が「>>」に隠れても、★ と停止は見えたまま。
  - 記録中の警告（音が入らないチャンネル。DEC-MTG-020）とオフレコ中の知らせは、真ん中の文字起こしの上の帯に出る。「話者の区別は記録を止めたあとに行います」は見出しの下に小さく出る。Whisper / Gemini で記録しているときは、文字起こしの欄に「記録を止めたあとに文字起こしします」と出る（REQ-MTG-003 の食い違いの中身は変えない）。
  - 記録中に AI チャットを開いても、真ん中の文字起こしは見えたまま（REQ-MTG-040）。
  - 記録を止めるとき、メモの入力欄に打ちかけの文があれば、止めた時点のメモとして確定してから止める。
  - 記録を止めると、選んでいる会議は変わらず、真ん中が文書になり、上の帯に段階（「文字起こし」（Whisper / Gemini のときだけ）→「話者の区別」→「議事録」）のどこまで進んだかが出る。議事録を作らない設定（DEC-MTG-015）・使う発言がない会議では「議事録」の段階を出さない。終わると帯が消え、議事録とアクションアイテムが出る。
  - 処理の間、メモの欄は読むだけにし、「議事録ができたら書き足せます」と出す（処理中に書いた分が処理の結果で上書きされないように）。
- 出典: 2026-11-09 の依頼「会議ノートの UI をモダンに」、同日に「記録中も作り直す」と、配置を「真ん中に文字起こし」にすることを確かめた
- 対象: Mac
- 実装の場所: `LiveTranscriptView`（新しい見た目に作り直す）、`LiveSidePanel`、`LiveNotesPanel`、`MeetingRecorder`（処理の段階を状態として持つ `MeetingProcessingStage`。停止の前に打ちかけのメモを確定する）、`MeetingDocumentView` の状態の帯

### 変える要件（ユーザーの合意が要る）

## 設計判断の案

計画の中では D1〜D9 と呼ぶ。spec に書くときは DEC-MTG の 130〜138 番にする（120〜125 番は開いている PR #78 が使っている。spec に書く直前にもう一度確かめる）。

### D1 文書＋後ろ側のパネルは `NavigationSplitView` と `inspector` で作り、最小の幅を 1000 にする

- 決めたこと: 左の一覧は今の `NavigationSplitView` のサイドバー（220〜260）のまま。後ろ側のパネルは SwiftUI の `.inspector(isPresented:)`（幅 300〜560、初期値 360）にし、表示の有無を `meetingInspectorShown`、記録後のタブを `meetingInspectorTab` に覚える。真ん中の文書は最小 400pt とし、パネルの幅はそれを割らない範囲でだけ広げられる。ウインドウの最小の大きさを 900×520 から 1000×560 に変える（220＋400＋360＋余白）。ツールバーの後ろ端に `sidebar.trailing` のボタン、メニューの「表示」に「インスペクタを表示／隠す」（⌥⌘I）を足す。ガラスはツールバーと再生のバーだけにし、重ねない。右から左に書く言語（ar）では、パネルは左に出る（システムに任せる）。
- 理由: macOS 26 の標準の部品で、Liquid Glass の見た目・サイズ変更・キーボード操作・右から左の言語の配置が手に入る。最小の幅 900 では、サイドバーとパネルを出すと文書が 300pt を切り、要約もカードも読めない。
- 関係する要件: R1
- 対象: Mac

### D2 会議への操作は、ツールバーと「…」のメニューにまとめる

- 決めたこと: 記録後のツールバーは、前から「議事録の型（今の `MinutesTemplateMenu`）」「議事録を作り直す（⟳）」「書き出し（共有の印のメニュー）」「…（話者名…・Finder で表示・削除…）」「インスペクタ」。タイトルの欄・日時の行は文書の先頭に置く。日時は `DateFormatter`、長さは `DateComponentsFormatter`（例: 日本語で「25 分」）で書き、時刻と見間違えないようにする。参加者は話者の色の丸と名前を並べ、押すと「話者名」のシートを開く。
- 理由: 今は 5 つのボタンが本文の上で折り返している。使う頻度の低い操作（Finder・削除）はメニューに入れる。
- 関係する要件: R1, REQ-MTG-008, REQ-MTG-028
- 対象: Mac

### D3 状態は文書（記録中は文字起こし）の上の帯で出す

- 決めたこと: 次の状態を、真ん中の先頭の帯にする。帯は種類ごとに色（青・黄・赤みのオレンジ）と印を変え、右端に次にすることのボタンを置く。同時に起きたときは、優先の高い 2 本までを積んで出す。
  1. 進行中: 「議事録を作成中（段階）」「作り直しています（終わるまで今の議事録を出す）」
  2. 記録中の警告: 音が入らないチャンネル（DEC-MTG-020）、オフレコ中
  3. 失敗: `errorMessage`（話者分離の失敗など）。長い文は 1 行に切り、「詳しく」で全文（選んでコピーできる）。「閉じる」で、アプリを終えるまでその会議では出さない
  4. 古い: 議事録に使う発言を変えた（DEC-MTG-092。「作り直す」のボタン）
- 理由: 長いオレンジの文章が見出しを押し下げるのをやめ、何をすればよいかを 1 か所で示す。失敗の帯は作り直しが成功するまで消えない（`errorMessage` が残る）ので、閉じられるようにする。
- 関係する要件: REQ-MTG-013, R1, R5, REQ-MTG-045
- 対象: Mac

### D4 要約とアクションアイテムを文書の先頭に出す

- 決めたこと: 議事録の Markdown を見出し `## ` で節に分け、最初の節を「要約」として先頭に、続けて `Meeting.resolvedActionItems` のカードを出し、残りの節を本文として出す。カードが 1 件以上あるときは、型の見出し（`minutes.actionHeading*` の言語ごとの文言と、保存したテンプレート・カスタムの型でも共通の `## ${actionHeading}`）の節を本文から外す。カードの各行は、やること・担当・期限・根拠の時刻の印。リマインダーに登録済みの行には、ベルの印を出す（四角のチェックボックスは使わない。完了のチェックに見えて押したくなるため）。カードの右上に「リマインダーに登録…」（今の機能）を置く。`minutes` の文字列は変えない。検索の飛び先は、描いた行の行番号をそのまま ID にし、外した節の行はカードの同じ順番の行へ読み替える。
- 理由: 会議のあと最初に読むのは要約と「やること」（ユーザーが選んだ構成の順番、Grain・Fathom と同じ）。文字列は変えないので、書き出し・検索・Windows との互換は今のまま。
- 関係する要件: REQ-MTG-018, R1, REQ-MTG-015
- 対象: Mac

### D5 引用は議事録の Markdown の中の `[12:34]` で受け取り、書き出しでは取り除く

- 決めたこと:
  - プロンプトに新しいキー `minutes.citations` を足し、Mac と Windows の `MinutesPrompt` で `minutes.actionItems` のあとに入れる（`minutes.actionItems` は変えない）。中身は「要点の箇条書きの行末に、根拠になった発言の時刻を `[12:34]` の形で 1〜2 個付ける。はっきりしなければ付けない。チェックボックスの行には付けない。アクションアイテムの JSON には、根拠の時刻を `"at": "12:34"` として付けてよい」。訳で `[12:34]` が変わらないよう、`scripts/check-i18n.py` の `LITERALS` に足す。
  - 新しい `MinutesCitation` に、印の取り出し（`[m:ss]`・`[mm:ss]`・`[h:mm:ss]`、全角の［］）と取り除き（前の空白ごと）を置く。表示は今の `MeetingChat.linkingTimes`（DEC-MTG-084）と同じ規則でリンクにし、小さなカプセルで描く。会議の長さを 1 秒より多く超える時刻は無効の印にする。
  - 書き出し（`MeetingExport` の Markdown・テキスト・Slack 向け、`ReminderExporter`）では取り除く。`minutes.md` と `meeting.json` には残す。`ActionItem.parse(fromMarkdown:)`（DEC-MTG-064）は、読む前に行末の印を取り除く。
  - ローカルの AI・Apple の AI で要点にまとめてから議事録を作ったとき（DEC-COM-065）は、保存の前に印を取り除く。
  - `ActionItem` に任意の `at`（文字列）を足す。Windows の `ActionItem` にも足し、読み書きで落とさない（`reminderID` と同じ扱い）。
  - Windows は、議事録の表示と書き出しで同じ規則で印を取り除く（`Hanasu.Core` に同じ関数）。
- 理由: 文字起こしの各行はもう `[時刻] 話者: 発言` の形で AI に渡しているので、同じ形で返させるのがいちばん確か。`minutes` の文字列に入るので、検索・保存の仕組みを変えずに済む。Mac と Windows で同じ文面を送る決まり（REQ-COM-061・DEC-COM-102）を守る。
- 関係する要件: R3, REQ-COM-061
- 対象: Mac / Windows

### D6 再生は 2 つの音声を `AVMutableComposition` で重ね、チャンネルのずれは `audioStartOffsets` に残す

- 決めたこと: `me.m4a` と `others.m4a` を 1 つの `AVMutableComposition` の 2 つの音声トラックとして、それぞれ録音開始からのずれ（DEC-MTG-006 の `ChannelTranscriber.audioStartOffset`）だけずらして入れ、`AVPlayer` で再生する。消音は `AVAudioMix` のトラックごとの音量を 0 にする。ずれは、Windows 版がもう書いている `meeting.json` の `audioStartOffsets`（`{"me": 0.12, "others": 0.31}`）に Mac も記録を止めたときに書き、読む（DEC-MTG-108 の「Windows 版だけが書く」を直す）。項目のない今までの会議は 0 として扱う。再生位置は 0.25 秒ごとに見て、`MeetingChat.lineIndex` で今の発言を引く。速さは `AVPlayer.rate`（声の高さを変えない `audioTimePitchAlgorithm = .timeDomain`）。記録の開始・音声入力の開始を `MeetingRecorder`・`DictationController` から知らせ、再生を止める。
- 理由: 2 つの `AVAudioPlayer` を同時に動かすより、1 つの時間軸でシーク・速さ変更ができてずれない。同じ意味のキーを 2 つにしない。
- 関係する要件: R4, REQ-MTG-010
- 対象: Mac

### D7 処理の段階を状態として持ち、処理中のメモは読むだけにする

- 決めたこと: `MeetingRecorder.State.processing` に、今の文の代わりに段階（`MeetingProcessingStage`: `.transcribing`（Whisper / Gemini のときだけ）、`.diarizing`、`.minutes`）と、出す段階の一覧を持たせる。帯は一覧を左から並べ、今の段階に印を付ける。議事録を作らない設定・使う発言がないときは `.minutes` を一覧に入れない。処理の間、文書のメモの欄は読むだけにする。記録を止める前に、`LiveNotesPanel` の入力欄に打ちかけの文があれば `appendNote` で確定してから止める。
- 理由: 今の処理の状態は自由な文だけで、段階を出せない。`process()` は止めた時点の会議を最後に保存するので、処理中のメモの編集は上書きされて消える。
- 関係する要件: R5, REQ-MTG-011
- 対象: Mac

### D8 議事録に使う発言の選択は、後ろ側のパネルの文字起こしの上の帯で行う

- 決めたこと: 今の `TranscriptSelectionBar`（DEC-MTG-093）を後ろ側のパネルの文字起こしの上に置く。ふだんは「議事録に使う発言 6 / 13」と「選ぶ…」だけの 1 行。「選ぶ…」を押すと、範囲・除いた話者・オフレコのカプセル（それぞれ解除）と「すべて元に戻す」「選び終える」を出し、チェックボックスを出す。選んでいる間は、文書が 400pt を割らない範囲でパネルを 520 まで広げ、終えたら元の幅に戻す。右クリック・「…」のメニューは今のまま。
- 理由: パネルの幅（360）では今の帯が収まらない。選ぶ間だけ広げれば、ふだんの文書の幅を削らずに済む。
- 関係する要件: REQ-MTG-044, REQ-MTG-045, REQ-MTG-046, R1
- 対象: Mac

### D9 一覧の日付のまとまり

- 決めたこと: 会議の開始の日で「今日・昨日・今週・先週・それより前は月ごと」に分ける。週の始まりは `Calendar.current.firstWeekday`（言語と地域の設定に任せる）。月の書き方は `DateFormatter.setLocalizedDateFormatFromTemplate("yMMMM")`。検索中は今と同じ検索結果の一覧を出す。描画の CLI は `--now` で基準の日時を固定できる。
- 理由: 会議は「この前の〇〇」と時期で探すことが多い。
- 関係する要件: R2
- 対象: Mac

## 仮に決めたこと（了承のときに見てほしい）

- 再生のスライダーに話者ごとの色の区間と「ここ重要」の位置を出す（Grain・Fathom の型）。削っても再生と同期の要件は満たせる。
- ウインドウの最小の大きさを 900×520 から 1000×560 に広げる（D1）。
- 引用の印を押したときは再生を始めず（再生中なら位置だけ移る）、文字起こしの時刻を押したときは再生を始める。
- 失敗の帯の「閉じる」は、アプリを終えるまでの間だけ効く（保存しない）。

## 実装のときに変えたこと

2026-11-09 の実装で、`--render-meeting-window` の確かめから次を変えた（spec の DEC-MTG-130・137 に理由を書いた）。

- ウインドウの最小の大きさは 1000×560 ではなく **1040×560**（一覧 260 ＋ 文書 400 ＋ パネル 360 ＋ 区切り）。
- 後ろ側のパネル（`inspector`）は、真ん中の画面ではなく `NavigationSplitView` に付けた。真ん中に付けると、macOS 26 で一覧とパネルが真ん中に重なるため、左右に並べる画面が一覧の幅を 2 回数えた最小の幅を求め、最小の大きさで中身がはみ出した。文書にも `minWidth`・理想の幅を持たせない。
- 発言を選ぶ間にパネルを 520 まで広げるのはやめた（幅の決まりを途中で変えても今の幅は変わらず、広げた幅で最小の幅を求めるとはみ出す）。カプセルは折り返す。
- 再生のバーは、狭いときに時刻を外し、速さと消音を「…」のメニューにまとめる（`ViewThatFits`）。
- メニューの「表示」に「インスペクタを表示／隠す」は足さず、ツールバーのボタン（⌥⌘I）にした。
- 処理中は「ここ重要」の欄を出さない（発言がまだないため）。
