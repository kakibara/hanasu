# Hanasu 利用ガイド

使い方・設定・ユーザー辞書の詳しい説明です。概要とダウンロードは [README](../README.ja.md)、実装済みの要件は [spec](spec/)、作りは [design](design/) にあります。

## できること

話した内容を Gemini で自然な日本語に整えて、カーソル位置に入力する macOS メニューバーアプリ（Typeless 風）。

- 音声認識: macOS 26 内蔵の音声認識エンジン（`SpeechAnalyzer` + `SpeechTranscriber`、`DictationTranscriber` も選択可）。オンデバイスで処理。設定で Whisper（WhisperKit。Mac の上で動かす）か Gemini（音声を送る）にも切り替えられる
- 整形: Gemini（初期値 `gemini-3.5-flash-lite`）。Google AI Studio の API キーか、Vertex AI のサービスアカウントで呼ぶ
- 入力: クリップボード + ⌘V（元のクリップボードは自動で戻す。貼り付け先が受け取らなかったときは、最新の結果をクリップボードに残す）
- 翻訳して入力: `⌥⇧ Space` で録音するか、録音中の表示で「English」を選ぶと、話した内容を AI が自然な英語に翻訳して入力する。設定の「一般」→「翻訳する言語」で日本語も選ぶと、表示に「日本語」が出て、英語などで話した内容を日本語に訳して入力できる（既定は English だけ）
- 選択を声で編集: 文章を選択して `⌃⌥⌘ E` を押し、「もっと丁寧に」「箇条書きにして」「英語にして」のように話すと、Gemini が書き換えて選択範囲に貼り付ける
- 履歴: 結果と文字起こしの原文を残し、検索・コピーできる。整形に失敗した文は原文から整え直せる。入力先がずれたら `⌥⇧ V` で最後の結果をもう一度入力

会議の記録機能もあります（Google Meet・Slack ハドル・Teams など）。マイクを「自分」、Mac で鳴っている音を「相手」として録り、文字起こしと Gemini の議事録を `~/Documents/Hanasu/Meetings/` に保存します。メニューバー →「会議の記録を開始」か `⌃⌥⌘ M`。イヤホンの利用を推奨します。Zoom・Teams・Slack ハドル・Webex・FaceTime・ブラウザ（Google Meet など）がマイクを使い始めると「会議を記録しますか？」と提案します（自動では記録しません）。
記録中は会議ノートにメモを書いたり、`⌃⌥⌘ H` かボタンで「ここ重要」の印を付けたりでき、議事録はそれを優先してまとめます（記録後にメモを直して作り直すこともできます）。文字起こしの字幕をほかのアプリの前面に出すこともできます。
記録中の画面の右側を「AI チャット」に切り替える（`⌘J`）と、それまでの文字起こしとメモをもとに AI に質問できます（「ここまでを要約」「決まったこと・宿題」などはボタン 1 つ）。続けて聞くと前のやりとりを踏まえて答え、答えの中の時刻を押すと文字起こしのその発言へ移ります。残したい答えは「メモに残す」で議事録に反映できます。記録のあとも会議ノートの「AI チャット」タブで続けられます（会話そのものは保存しません）。入力欄の下の「送り先」で、その会議の会話に使う AI とモデルを、設定の既定から切り替えられます（アプリを終了すると既定に戻ります）。
別の作業をしていて急に質問を振られたときは、会議ツールを前面にしたまま字幕の「何を聞かれた？」か `⌃⌥⌘ A` を押すと、相手の直近の発言と、AI がまとめた「聞かれたこと」と「背景」が前面のパネルに出ます（直近 10 分の会話をもとにします。「チャットで続ける」で続けて聞けます）。字幕を出したまま記録を終えると、次の記録でも字幕が出ます。
会議ノートでは、過去の会議の文字起こしと議事録を横断して検索でき（`⌘F`）、「先週の定例で何が決まった？」のように質問すると、関係する会議をもとに Gemini が根拠の会議を引用して答えます（✦ ボタン）。

議事録は型（自動・定例・1on1・商談・ブレスト・カスタム）を選んで作れます。記録を始める前に会議ノートの左下で選ぶか、あとから会議ノートで選び直して作り直します。アクションアイテム（担当・内容・期限）は決まった形で取り出し、会議ノートの「書き出し」から Markdown・Slack 向けのコピー、.md / .txt の保存、リマインダーへの登録ができます。

文書の地図は [docs/README.md](README.md)。実装済みの要件・設計判断は [docs/spec/](spec/)、設計・技術選定は [docs/design/dictation.md](design/dictation.md)（音声入力）と [docs/design/meeting.md](design/meeting.md)（会議の記録）、計画は [docs/roadmap.md](roadmap.md)。

## 必要なもの

- macOS 26 (Tahoe) 以降、Apple Silicon
- Gemini の認証情報: API キー（[Google AI Studio](https://aistudio.google.com/apikey)）か、Vertex AI ユーザー権限のあるサービスアカウントの JSON 鍵
- 自分でビルドする場合: Xcode Command Line Tools（Swift 6.2）

## インストール（リリース版）

1. [Releases](https://github.com/kakibara/hanasu/releases) から `Hanasu-<バージョン>-macOS.zip` をダウンロードして展開し、`Hanasu.app` を「アプリケーション」フォルダに入れる。
2. Apple の公証（notarization）を受けていない自己署名のアプリなので、そのままでは「開発元を確認できない」として開けません。次のどちらかで開いてください。
   - 一度開こうとして確認が出たら「完了」を押し、システム設定 → プライバシーとセキュリティ の下にある「このまま開く」を押す（macOS 15 以降は、右クリック →「開く」では開けません）
   - またはターミナルで `xattr -dr com.apple.quarantine /Applications/Hanasu.app` を実行してから開く
3. 初めて起動すると、使い方の案内（オンボーディング）が開きます。使う AI を選び（おすすめは、この Mac の中で動く Gemma 4 E4B。選ぶと案内の中でモデル（約 4.6 GB）をダウンロードします。Gemini・Claude・Apple も選べます）、主な機能と設定の Tips を見て、最後に許可を済ませます。2 回目からは起動しても画面は開きません。設定画面は、メニューバーのアイコンか Dock のアイコンを右クリックしたメニューの「設定…」で開きます（Dock のアイコンを押すだけでは開きません。以下「使い方」）。案内はメニューの「Hanasu の使い方…」でいつでも開き直せます。

## 使い方

1. 初めての起動では案内の中で使う AI を選べます。あとから変えるときは、設定画面の「AI」で音声入力と会議に使う AI（Gemini・Claude・ローカル・Apple）を選び、Claude なら API キーを、Gemini なら API キーかサービスアカウントの JSON ファイルを保存する。「整形を試す」で動作を確かめられる。
2. 入力したい場所にカーソルを置き、`⌥ Space` を押して話す。
3. もう一度 `⌥ Space` を押すか、画面下の表示の「■ 完了」をクリックすると、整形された文章が入力される。録音中に `Esc` か「取消」で取り消し。
4. 英語で入力したいときは、`⌥⇧ Space` で録音を始めるか、録音中に画面下の表示で「English」をクリックしてから止める。英訳した文章が入力される。翻訳する言語に日本語も選んでいれば、「日本語」をクリックして止めると和訳した文章が入力される。
5. 書いた文章を直したいときは、その文章を選択して `⌃⌥⌘ E` を押し、どう直すかを話す（例:「もっと丁寧に」「箇条書きにして」「英語にして」「3 行に要約して」）。もう一度 `⌃⌥⌘ E` を押すと、Gemini が書き換えた文章で選択範囲が置き換わる。元に戻すときは、そのアプリで ⌘Z。メニューバーの「選択を声で編集」からも始められる。
   - Gemini の認証情報とアクセシビリティの許可が必要です。
   - 選択した文章は Gemini に送られます。
   - 選択をアクセシビリティ API で読めないアプリでは、⌘C で写し取って読みます（クリップボードはすぐ元に戻します）。
6. 入力先のアプリに合わせて文体が変わる（Slack などのチャットはくだけた短い文、メールは丁寧な文で段落を分ける、Pages・Word・Notion は書き言葉）。設定の「アプリ別」で、アプリごとのプリセット・追加ルール・既定の出力言語（話した言語／English）を変えられる。
7. 署名・自己紹介・住所・会議 URL のような決まった文章は、設定の「スニペット」で起動フレーズと本文を登録しておくと、「メールの署名」と話すだけで本文がそのまま入力される（Gemini には送らない。英訳モードでも訳さない）。「よろしくお願いします、メールの署名」のように区切って言えば、文の途中でも置き換わる。
8. 入力先がずれて結果が消えたときは、入れたい場所で `⌥⇧ V` を押すと、最後の結果をもう一度入力する。録音中に別のウインドウへ移ったなどで貼り付けが届かなかったときは、最新の結果がクリップボードに残っているので、入れたい場所で ⌘V を押してもよい。設定の「一般」→「貼り付けが届かなかったとき」で、そのときに履歴のウインドウを開くようにもできる。
9. メニューバー →「履歴を開く…」で、これまでの結果と原文を検索・コピーできる。Gemini が失敗して原文のまま入力したもの（⚠︎）は、「整形し直す」「英訳し直す」（日本語を選んでいれば「和訳し直す」も）で整え直せる。履歴は `~/Library/Application Support/Hanasu/History/` に保存され、初期値では 1000 件・30 日まで残る。

初回は次の許可を求められます。

- マイク・音声認識: 初めて録音するときにダイアログが出る
- アクセシビリティ: システム設定 → プライバシーとセキュリティ → アクセシビリティで Hanasu をオン（⌘V の自動送信に必要）

署名用の証明書がない環境ではアドホック署名になり、再ビルドのたびにアクセシビリティの許可が外れます（設定でオンに見えても効かない）。最初に一度だけ次を実行しておくと、ローカル用の自己署名証明書で署名するようになり、再ビルドしても許可が保たれます。

```bash
./scripts/create-signing-cert.sh
```

許可が外れてしまった場合は、アクセシビリティの一覧から Hanasu を削除（−）して追加し直してください。

## 設定できること

ショートカット（音声入力・翻訳して入力・選択を声で編集）、翻訳する言語（English・日本語）、トグル／押している間だけ録音、整形などに使う AI とモデル（下の「AI と API キー」）、ユーザー辞書と置き換えルール、追加の整形ルール、アプリ別の文体（プリセット・追加ルール・既定の出力言語）、スニペット（起動フレーズと本文）、効果音。

文字起こしのエンジン: 音声入力と会議の記録で別々に、Mac 標準（既定。SpeechTranscriber / DictationTranscriber）・Whisper（Mac の上で動かす。tiny / base / small / large-v3-turbo のモデルを選ぶと、その時点でダウンロード。取り消し・削除も設定から）・Gemini（録った音声を Google に送って文字起こし）から選べます。Whisper と Gemini は録音を止めてからまとめて文字起こしするので、録音中は文字が出ません（HUD には音量の目安を出します）。会議の記録では、記録のあとにチャンネルごとに時刻つきで文字起こしし、話者分離に回します。

履歴: 保存するか、残す件数と期間、録音した音声も残すか（既定はオフ）、「最後の結果をもう一度入力」のショートカット。

画面の文脈（既定はオフ）: 設定の「AI」でオンにすると、録音を始めたときに前面のウインドウのタイトルと入力欄のカーソル前後の文章（各 500 文字まで）を読み、参考情報として AI（Gemini か Claude）に渡します。画面にある固有名詞の表記（例: 「庄司さん」→ 画面にある「東海林さん」）や書き方に合わせて整えます（英訳でも使います）。パスワード欄と、除外に入れたアプリ（既定で 1Password などのパスワードマネージャー）は読みません。文脈に書かれた指示には従わず、文脈の文章を出力に含めないよう Gemini に指示しています。

スクリーンショットの文字（Mac・既定はオフ）: 同じ欄の「スクリーンショットの文字も AI に渡す」をオンにすると、録音を始めたときにすべての画面を撮り、写っている文字を Mac の中で読み取って、その文字だけを AI に渡します（画像は送らず、保存もしません）。横に開いた資料や別の画面にある型番・固有名詞（例: 「キューエックスセブンエス」→ 画面にある「QX-7s」）の表記に合わせます。画面収録の許可が要り、トグルをオンにしたときに求めます。許可していると、録音中の HUD にカメラのボタンが出て、その録音だけ使う・使わないを切り替えられます。Hanasu・除外アプリ・通知・認証のダイアログは写しません。

会議の記録: 録音するスピーカーとマイク、マイク側も話者を分ける（会議室など）、議事録を作るか（AI とモデルは設定の「AI」）、音声ファイルを残すか、会議の自動検出（オン／オフと対象のアプリ）、「ここ重要」のショートカット。

### AI と API キー

設定の「AI」の先頭の「文字起こし AI」で、音声を文字にするエンジン（音声入力と会議の記録で別々）を選びます。その下の「文字起こしのあとの AI」で、文章を処理する AI を、**音声入力整形**（整形・英訳・選択の編集）・**議事録**（議事録・辞書の候補）・**AI チャット・質問**（会議の AI チャット・会議への質問。Mac）で別々に選べます。

- ローカル（Mac の既定）: Gemma 4 E4B（おすすめ）などのモデルを、この Mac の中で動かします。文章をネットに送りません。モデルがないまま整形・議事録の作成を始めると、ダウンロードするかを尋ね、「ダウンロードする」を選ぶと進み具合のバーを出して取り、終わったら続けて整形します（以前から Gemini で使っていた人は、上げても Gemini のままです）。
- Gemini（Windows の既定）: モデルは自由に入れられます（音声入力整形の初期値 `gemini-3.5-flash-lite`、議事録と AI チャット・質問の初期値 `gemini-3.8-flash`）。認証は Google AI Studio の API キーか、Vertex AI のサービスアカウント。
- Claude（Anthropic）: [Claude Console](https://console.anthropic.com/settings/keys) で発行した API キーを入れます。モデルは Claude Haiku 5.5（音声入力整形と AI チャット・質問の初期値）・Sonnet 5.5（議事録の初期値）・Opus 5.5 から選びます。「接続を試す」でキーを確かめられます。キーが正しくないときは「API キーが正しくありません（401）」と出ます。
- Claude には音声を送りません。文字起こしは「AI」→「文字起こし AI」で選んだエンジンが行います（Gemini の認証は、文字起こしのエンジンに Gemini を選んだときにも使います）。

API キーの扱い:

- Mac 版はキーをキーチェーンに保存し、Hanasu 以外のアプリが読もうとすると、macOS がログインのパスワードを求めるようにしています。設定画面には末尾 4 文字だけを出し、削除もできます。設定ファイルやログにはキーを書きません。
- Windows 版は、DPAPI（既定）か Windows Hello の鍵で暗号化して保存します（[windows/README.md](../windows/README.md)）。
- ただし、どちらも同じユーザーで動く悪意のあるプログラムからは守りきれません（確かめた結果と理由は [design/security.md](design/security.md)）。Apple の公証もコード署名もない自己署名のアプリなので、ダウンロードした zip が本物かは、リリースに載せた SHA-256 で確かめてください（`shasum -a 256 Hanasu-<バージョン>-macOS.zip`）。

### ユーザー辞書

設定の「辞書・ルール」で、固有名詞や専門用語を登録できます。表とテキストのどちらでも編集できます。

```
Hanasu                              … 語だけ。音声認識と AI のヒントにする
ストックマーク => Stockmark            … 置き換えルール。文字起こしの「ストックマーク」を「Stockmark」にする
えーにゅーす, エーニュース => Anews     … 読み（聞こえ方・誤認識）は「,」で区切って複数書ける
```

- 置き換えルールは文字起こしの結果に必ず当てるので、Gemini で整形しないときも効きます。
- 英字の大文字小文字・全角半角・空白の有無は区別しません。英字やカタカナの語の途中では置き換えません（`マーク => Mark` は「マークダウン」の中では効かない）。細かい規則は [docs/design/dictation.md](design/dictation.md) の 5.4。
- 「候補を探す」を押すと、今回の起動後の音声入力の結果と、新しい順に 5 件の会議の文字起こし・議事録から、設定の「AI」で「議事録」に選んだ AI が辞書の候補を挙げます（Mac 版）。選んだものだけが辞書に入ります。会議の中身を送る先は、その AI だけです（「ローカル」か「Apple」なら、この Mac の外には送りません）。
- 会議ノートで開いた会議からも候補を探せます（Mac 版・Windows 版。Mac は上の並びの辞書のアイコン、Windows は「辞書…」）。
  - **この会議から辞書の候補を探す…**: その会議の文字起こしと議事録だけを読んで候補を挙げます。オフレコの区間と、議事録に使わないと除いた発言は送りません。会議が長くて全部を読めなかったときは、読んだ範囲（最初の約何分か）を出します。「この会議の文字起こしにも辞書を当てる」をオンにして追加すると、足した語がすぐその会議の文字起こしに当たります。
  - **今の辞書をこの会議に当て直す**: 設定で手で足した語や、表記を直した語を、その会議の文字起こしに当て直します。
  - **この会議を認識したままの文に戻す**: 辞書で置き換える前の、音声認識のままの文に戻します（辞書は変えません）。
  - 文字起こしが変わっても、議事録は自動では作り直しません。議事録の上に「文字起こしか、議事録に使う発言を変えました」と出るので、「議事録を作り直す」で作り直してください。
- 設定の会議の欄の「文字起こしに辞書の置き換えルールを当てる」（既定でオン）がオンなら、記録を止めたあとの文字起こしにも置き換えルールを当ててから議事録を作ります。音声認識のままの文も残すので、あとから戻せます。記録中の文字起こしと字幕には当てません。

リマインダーへの登録は、会議ノートで「リマインダーに登録」を押したときに初めてアクセスの許可を求めます。

## Windows 版

Windows 10（2004 以降）/ 11 向けの版を [windows/](../windows/) で作っている（C# / .NET 8 / WPF）。音声入力と会議の記録の両方がある。

- タスクトレイに常駐し、`Ctrl + Alt + Space` で音声入力、`Ctrl + Alt + Shift + Space` で翻訳して入力する（設定で変えられる。翻訳する言語は設定 → 一般で English・日本語から選ぶ）
- 文字起こしは Windows 標準の音声認識（既定）・Whisper（PC の上で動かす）・Gemini から選ぶ。整形と英訳は Mac 版と同じ指示で Gemini が行う
- 会議の記録は `Ctrl + Alt + Shift + M`（またはタスクトレイのメニュー）で始め・止める。マイクを「自分」、WASAPI ループバックで録った PC の音を「相手」として別々に録り、記録のあとに Whisper（既定）か Gemini で文字起こしし、sherpa-onnx で相手側の話者を分け、Gemini で議事録を作る
  - 保存先は `ドキュメント\Hanasu\Meetings\<日時>\`。`meeting.json` は Mac 版と同じ形なので、Mac で作った会議のフォルダをそのまま会議ノートで開ける
- ビルド・配布物の作り方・Mac 版との差は [windows/README.md](../windows/README.md)
